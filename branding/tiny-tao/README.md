# tiny-tao api 品牌资源

`home.html` 使用 Sub2API 后台的自定义首页设置；`site.css` 和 `logo.svg` 通过站点的 `/brand/tiny-tao/` 路径提供。样式限定在 `#tiny-tao-home` 内，站名、Logo 与副标题使用系统已有品牌设置，同步到登录页和控制台。

首页不依赖外部字体、统计脚本或第三方图片。控制台、模型列表、锚点导航均为普通链接；API 地址可直接选择复制。窄屏重排内容，系统偏好减少动态效果时关闭动画。

部署时先备份现有品牌设置，再上传三个静态文件，将 `home.html` 写入 `home_content`，站名设为 `tiny-tao api`，Logo 设为 `/brand/tiny-tao/logo.svg`。页脚保留原项目和 LGPL-3.0 许可证链接，不表示上游项目对独立服务提供背书。

当前部署由 Caddy 将 `/brand/tiny-tao/*` 映射到仅含 CSS 和 SVG 的 `/var/www/tiny-tao-brand/`，其余请求仍交给原后端。Logo 也可以通过后台上传，使登录页、控制台和浏览器图标使用同一品牌标识。回滚时恢复已备份的品牌设置和静态资源路由即可，无需迁移业务数据。

当前模型广场未启用，首页只链接实际可访问的控制台与站内接入说明，不展示未经确认的商用价格或性能承诺。桌面 1500px 和手机 390px 视口均完成线上视觉检查，手机无横向溢出，所有页内锚点均有目标。

正式收款启用前，保留首页“自助充值将在正式收款验证后开放”的说明。沙箱支付只能在独立测试部署中使用，不能据此宣称正式收款已经开通。

## 邮箱验证码模板

`email/templates.json` 列出 `auth.verify_code` 的中英文标题、HTML 文件和发件人显示名称。在后台「系统设置 → 邮件模板」选择对应事件与语言，分别保存标题和 HTML；SMTP 发件人显示名称统一为 `tiny-tao api`。

此事件由注册、绑定邮箱、OAuth 补充邮箱和 TOTP 验证共同使用，文案只描述邮箱验证，不限定为注册成功通知。验证码与有效期使用服务端变量，不在模板里写死。模板不含外部图片、字体、追踪像素、短链接或营销内容，唯一链接为站点首页。

应用前备份这两个模板的已有覆盖值，以及原 SMTP 显示名称。回滚时恢复备份；原本没有自定义模板的，使用后台「恢复官方模板」。模板保存后随下一封验证码邮件生效，无需重启服务。

模板优化不保证进入收件箱。需要结合 Gmail 的实际分类、发信认证、域名与发送 IP 信誉评估效果；SMTP 接收成功只能证明发送链路接受了邮件。仅针对用户主动发起的操作发送，避免连续重复测试或人为批量“养号”。
