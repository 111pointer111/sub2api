# tiny-tao api 支付沙箱验收

验收时间：2026-11-02（Asia/Shanghai）。使用支付宝官方沙箱应用及测试买家，不涉及真实资金。

## 环境与结果

测试使用独立数据库、Redis、用户和后端实例，不配置真实模型上游。沙箱网关为 `https://openapi-sandbox.dl.alipaydev.com/gateway.do`。

| 检查 | 实际结果 |
| --- | --- |
| 付款前测试余额 | 0 |
| 零余额发起模型调用 | HTTP 403，`INSUFFICIENT_BALANCE` |
| 伪造签名付款回调 | HTTP 400，余额仍为 0 |
| 官方沙箱买家付款 | 1.00 CNY 模拟资金，订单 1 进入 `COMPLETED` |
| 签名回调到账 | 测试余额从 0 增加为 1 |
| 重放同一有效回调 | HTTP 200 / `success`，余额仍为 1 |
| 正式账号余额 | 保持 0，未计入沙箱额度 |

此处采用测试换算比例 1，仅用于验收，不代表正式充值价格。未通过真实模型请求验证扣费；零余额拦截和支付到账已实测。

测试后已移除临时公网回调路由，停止测试后端、测试 Redis 和回调收集器。独立数据库和私有验收记录保留。密钥、买家密码、登录令牌及原始回调不进入代码仓库。

## 源码验证

- 支付服务商包单元测试通过，覆盖正式默认网关、沙箱网关及无效环境拒绝；新用例在修改前失败。
- 针对性服务测试通过，覆盖历史订单环境锁定、未完成订单保护、重复通知、金额不匹配和充值恢复。
- 前端 3 个相关测试文件共 30 项通过，TypeScript 类型检查通过。
- Linux amd64 后端构建通过，并用于独立沙箱部署。

## 交付边界

支付宝沙箱环境选择和历史订单保护在源码及独立测试实例中验证。正式后端程序版本未升级，仍运行标准计费模式；正式收款未开通。品牌首页通过现有自定义首页设置及静态品牌资源上线。
